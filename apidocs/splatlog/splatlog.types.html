splatlog.types¶

Type definitions for splatlog.

Provides type aliases, protocols, type guards, and conversion functions used throughout the package. Many types accept a variety of input formats that can be converted to a canonical form (the To* convention).

splatlog.types.Verbosity¶

‘NewType(…)’

Representation of a common “verbose” flag, where the repetition is stored as a count — no flag is 0, -v is 1, -vv is 2, etc.

Implemented as a typing.NewType because using bare int in verbosity/level associations easily loses context. Consider

{
    0: "warning",
    1: "info",
    2: "debug",
}

compared to

{
    Verbosity(0): "warning",
    Verbosity(1): "info",
    Verbosity(2): "debug",
}

The second example makes it much easier to remember what the keys represent. As Verbosity is an int at runtime the first form can still be used in the REPL, as well as in scripts and programs that forgo type checking.

splatlog.types.Rich: TypeAlias¶

None

An object that implements rich rendering. It is the union of rich.console.ConsoleRenderable and rich.console.RichCast.

  1. ConsoleRenderable — directly renders itself as a stream or sequence of plain or styled text and other Rich objects, with the rich.console.Console available for reference.

    Implements

    def __rich_console__(
    self,
    console: rich.console.Console,
    options: rich.console.ConsoleOptions,
) -> rich.console.RenderResult:
    ...

    where rich.console.RenderResult is a Iterable of

    • str — plain text.

    • rich.segment.Segment — styled text.

    • Other Rich objects that can then be rendered-down further.

    As seen in the __rich_console__() method signature, a Console and ConsoleOptions are passed in as arguments, allowing implementors to inspect the available rich.style.Style and specify fallbacks.

  2. RichCast — converts itself to plain text or another Rich object.

    Implements

    def __rich__(
    self,
) -> rich.console.ConsoleRenderable | rich.console.RichCast | str:
    ...

    to convert itself into one of:

    • str — plain text.

    • ConsoleRenderable — directly renderable, as detailed above.

    • RichCast — another object that implements __rich__(), where the process can be repeated until a str or ConsoleRenderable is reached or a loop is detected.

class splatlog.types.RichTyped¶

Bases: typing.Protocol

An extension of the “rich dunder protocol” system to allow classes to control how their type is printed by Rich.

As an extension, the protocol is not used by Rich itself, but is preferred by splatlog.rich.enrich_type() to format object types.

Examples

The method should be defined as a classmethod since the class is the receiver that makes sense. In this case, we’ll define a class A that will print it’s module and class name in a rich.panel.Panel.

>>> from rich.panel import Panel

>>> class A:
...     @classmethod
...     def __rich_type__(cls) -> RenderableType:
...         return Panel(cls.__module__ + "." + cls.__qualname__)

Note that both the A class and instances will test as expressing the protocol.

>>> isinstance(A, RichTyped)
True

>>> isinstance(A(), RichTyped)
True

To wrap things up we’ll create an instance of A, extract it’s “Rich type” with splatlog.rich.enrich_type, and print our panel!

>>> from rich.console import Console
>>> from splatlog.rich import enrich_type

>>> a = A()
>>> Console(width=40).print(enrich_type(a))

│ splatlog.types.A                   │
╰──────────────────────────────────────╯

splatlog.types.OnReducerError: TypeAlias¶

None

Ways to handle when a splatlog.json.JSONReducer raises an Exception in is_match() or reduce() as called in splatlog.json.JSONEncoder.default():

  • "raise" (default) — raise the error. Exception.add_note() is used to add context.

    Neither is_match() nor reduce() (preconditioned on is_match) are expected to raise errors, and you typically want to know if something goes wrong when encoding an object, rather than when trying to decode it later.

  • "continue" — ignore the error and continue with the next reducer.

    This mode exists specifically for encoding JSON logs, where we want to be able to pass any object and prefer a splatlog.json.FALLBACK_REDUCER encoding (type and repr()) to failure.

splatlog.types.OnConflict: TypeAlias¶

None

Strategy for handling conflicts when registering a named handler that already exists: "raise", "ignore", or "replace".

  • "raise": Raise an exception.

  • "ignore": Pretend it didn’t happen.

  • "replace": Clobber the old handler, installing the new one.

splatlog.types.is_rich(x: object) → TypeIs[Rich]¶

Is an object “rich”? This amounts to:

  1. Fulfilling one of the protocols:

    • rich.console.ConsoleRenderable — having a __rich_console__ method, the signature of which is:

      def __rich_console__(
    self,
    console: rich.console.Console,
    options: rich.console.ConsoleOptions
) -> rich.console.RenderResult:
    ...

    • rich.console.RichCast — having a `rich method, the signature of which is:

      def __rich__(self) -> rich.console.RenderableType:
    ...

  2. Not being a class (tested with inspect.isclass).

    This check is applied a few places in the Rich rendering code, and is there because a simple check like

    hasattr(renderable, "__rich_console__")

    is used to test if an object fulfills the protocols from (1). Those attributes are assumed to be instance methods, which show up as attributes on the class objects as well.

    The additional

    not isclass(renderable)

    check prevents erroneously calling those instance methods on the class objects.

splatlog.types.to_level(
value: ToLevel,
*,
case_sensitive: bool = False,
) → Level¶

Obtain a logging Level integer from more useful/intuitive things, like strings you might get from an environment variable or command line option.

Parameters

  • value: ToLevel value to convert.

  • case_sensitive: when False (default), both a given str value and its str.upper() transformation will be tried as level names.

    When True, level names must be verbatim.

Examples

int Values

Any integer is simply returned. This tracks the current logging module logic, in particular the _checkLevel function.

>>> to_level(logging.DEBUG)
10

>>> to_level(123)
123

>>> to_level(-1)
-1

No, I have no idea what kind of mess using negative level values might cause.

str Values

Integer levels can be encoded as strings. IDK if this will happen much in practice, but it’s easy to tell what you mean, so we handle it. Again, the integers don’t have to correspond to any named level.

>>> to_level("8")
8

We also accept level names.

>>> to_level("DEBUG")
10

By default, both the value and the str.upper() version are tried.

>>> to_level("debug")
10
>>> to_level("DeBuG")
10

If you specify case_sensitive behavior then level names must be exact.

>>> to_level("debug", case_sensitive=True)
Traceback (most recent call last):
    ...
TypeError: 'debug' is not a valid level name (case-sensitive)...

>>> to_level("DEBUG", case_sensitive=True)
10

This works with custom levels as well.

>>> logging.addLevelName(8, "LUCKY")
>>> to_level("lucky")
8

Other

Everything else can kick rocks:

>>> to_level([])
Traceback (most recent call last):
    ...
AssertionError: expected `<int | str>`
given `<list>` `[]`

  • "configured": Include only loggers with handlers or non-NOTSET level.

splatlog.types.fmt_level(level: ToLevel) → str¶

Format a logging level, displaying both the integer value and name.
