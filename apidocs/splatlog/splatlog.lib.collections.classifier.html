A rule-based classifier Mapping elements in T to classifications in C.

  • Each rule associates a Collection of type T to a classification of type C:

    rule: Collection[T] -> C

  • Classifying an element of type T finds a Collection that contains the element and returns the associated classification of type C:

    classify(item: T) -> C

  • If multiple rules match then first one wins (see rules documentation below).

Use Cases

A Classifier is used in splatlog.levels.VerbosityFilter to map splatlog.types.Verbosity to log splatlog.types.Level based on range collections.

Examples

>>> c = Classifier({
...     range(0, 5): "a",
...     range(5, 10): "b",
... })

>>> 3 in c
True
>>> c[3]
'a'
>>> 5 in c
True
>>> c[5]
'b'
>>> 11 in c
False

Below, rules for "a" and "b" overlap in elements 1 and 2. In c_a, the rule for "a" is given first and the "a" classification wins. In c_b, the order is reversed and the "b" classification wins.

The element/classification mapping can be clearly seen by converting the classifiers to dict.

>>> c_a = Classifier({
...     (0, 1, 2): "a",
...     (1, 2, 3): "b",
... })

>>> c_a[1]
'a'
>>> c_a[2]
'a'

>>> c_b = Classifier({
...     (1, 2, 3): "b",
...     (0, 1, 2): "a",
... })

>>> c_b[1]
'b'
>>> c_b[2]
'b'

>>> dict(c_a)
{0: 'a', 1: 'a', 2: 'a', 3: 'b'}

>>> dict(c_b)
{0: 'a', 1: 'b', 2: 'b', 3: 'b'}

Initialization

Create a classifier from a set of rules.

Parameters

  • rules: Mapping or Sequence of pairs where each Collection of elements in T is associated with a classification in C.

    Note

    Rules are matched on a first-wins basis. If have overlapping rules or want to control the matching order for efficiency reasons consider using the Sequence form to communicate explicit ordering. dict is defined as ordered since Python 3.7, but Mapping is not.

_rules: list[tuple[Collection[T], C]]¶

None

Classification rules, each a Collection of T paired with a classification in C.

Stored in order of priority, high to low (first wins).

__iter__() → Iterator[T]¶

Iterate over all classified elements, which are the keys in the Mapping sense.

Note

This method exists to satisfy the Mapping interface. It is not expected to be of much practical use, and may consume a surprising amount of resources.

Each classified element will appear once (no duplicates). This requires construction of a set taking the set.union() of the collections from all rules, then iterating over that set.

If you have use for the set itself use elements().

Examples

Below, rules for "a" and "b" overlap in elements 1 and 2, but iterating over the Classifier yields each element only once.

>>> c = Classifier({
...     (0, 1, 2): "a",
...     (1, 2, 3): "b",
... })

>>> for element in c:
...     print(element)
0
1
2
3
__len__() → int¶

Count the elements that can be classified, which are the keys in the Mapping sense.

Note

This method exists to satisfy the Mapping interface. It is not expected to be of much practical use, and may consume a surprising amount of resources.

Examples

Below, rules for "a" and "b" overlap in elements 1 and 2, but are counted only once in the len().

>>> c = Classifier({
...     (0, 1, 2): "a",
...     (1, 2, 3): "b",
... })

>>> len(c)
4
elements() → set[T]¶

Return the set of all classifiable elements.

May be useful on its own, but mostly here to support __iter__() and __len__() from the Mapping interface, where this set is the map keys.

Examples

Below, rules for "a" and "b" overlap in elements 1 and 2, but are counted only once in the len().

>>> c = Classifier({
...     (0, 1, 2): "a",
...     (1, 2, 3): "b",
... })

>>> c.elements()
{0, 1, 2, 3}
classifications() → set[C]¶

Return the set of all classifications.

Provided to compliment elements(), which returns the set of all classifiable elements. Relative the Mapping, the set of classifications are the map values.

Examples

Below, rules for "a" and "b" overlap in elements 1 and 2, but are counted only once in the len().

>>> c = Classifier({
...     (0, 1, 2): "a",
...     (1, 2, 3): "b",
... })

>>> c.classifications() == {'a', 'b'}
True

iter_rules() → Iterator[tuple[Collection[T], C]]¶

Iterate over the rules as (collection, classification) pairs, in priority order (first wins).

Examples

>>> c = Classifier({
...     range(0, 5): "a",
...     range(5, 10): "b",
... })

>>> for collection, classification in c.iter_rules():
...     print((collection, classification))
(range(0, 5), 'a')
(range(5, 10), 'b')
list_rules() → list[tuple[Collection[T], C]]¶

Return a shallow copy of the current (collection, classification) rules in priority order.

Examples

>>> c = Classifier({
...     range(0, 5): "a",
...     range(5, 10): "b",
... })

>>> c.list_rules()
[(range(0, 5), 'a'), (range(5, 10), 'b')]
