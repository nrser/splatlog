splatlog.lib.text.formatter¶

Text formatting infrastructure:

  • @formatter decorator creates text Formatter functions from FmtImpl implementations.

  1. Format function protocol Formatter and @formatter decorator,

  2. options class FmtOpts and keyword arguments FmtKwds,

as well as some other odds and ends.

class splatlog.lib.text.formatter.FmtKwds¶

Bases: typing.TypedDict

Keyword arguments type for FmtOpts fields.

Keys

Are exactly the attributes of FmtOpts, and documented there.

All keys are optional (via total=False).

Usage

Keyword arguments of type FmtKwds are used to construct FmtOpts:

>>> def f(**kwds: typing.Unpack[FmtKwds]):
...     return FmtOpts(**kwds)

This lends itself to an especially nice, concise syntax for specifying options:

>>> opts = f(q=True, i_fmt="{:_}")
>>> opts.q
True
>>> opts.i_fmt
'{:_}'

Initialization

Initialize self. See help(type(self)) for accurate signature.

class splatlog.lib.text.formatter.FmtOpts¶

Options controlling text formatting behavior.

This is a frozen dataclass; use dataclasses.replace() to create modified copies. The provide() decorator allows functions to accept these options either as a final positional argument or as keyword arguments.

fallback: FmtFallback¶

None

Custom fallback formatter, or None to use the built-in rich.pretty.pretty_repr() fallback.

When None (the default), format_fallback() uses rich.pretty.pretty_repr() configured by:

  • depth → max_depth

  • items → max_length

  • chars → max_string

  • width → max_width

Set to any (object, FmtOpts) -> str callable to override — the options are passed through so custom fallbacks can use them too.

q: bool¶

False

quote — Add markdown-style backtick quotes around formatted objects, marking them as <code> spans

fqn: bool¶

True

Whether to include module names in formatted output.

fq_builtins: bool¶

False

“Fully-Qualified Builtins” — Whether to include the builtins module prefix for built-in types.

fq_typing: bool¶

False

“Fully-Qualified Typing” — Whether to include the typing module prefix — e.g. typing.Any versus Any.

sym: str | None¶

None

Include the symbol (argument or variable name) associated with the value.

Given `name` `<str>` `"holla"`
t: bool¶

False

type — Add the type of the value being formatted as well.

t_start: str¶

‘<’

Start delimiter for types and type hints.

t_end: str¶

‘>’

End delimiter for types and type hints.

t_opt_q: bool¶

True

Use ? suffix for typing.Optional types (including those defined as a typing.Union with None).

chars: int | None¶

None

Maximum string length before truncating.

Equivalent to the max_string parameter in rich.pretty.

depth: int | None¶

None

Maximum depth of nested data structures.

Equivalent to the max_depth parameter in rich.pretty.

items: int | None¶

None

Maximum number of items to show in containers before abbreviating.

Equivalent to the max_length parameter in rich.pretty.

Examples

>>> FmtOpts(items=3).fallback(list(range(10)))
'[0, 1, 2, ... +7]'
width: int | None¶

None

Desired maximum width of the formatted string.

Equivalent to the max_width parameter in rich.pretty.

s_raw: bool¶

False

Don’t quote str as values, just return them as the formatted string.

ls_sep: str¶

‘,’

List separator. fmt_list() will stick this between items (along with a space).

ls_conj: str | None¶

None

List conjunction. When None fmt_list() will use the FmtOpts.ls_sep throughout, like A, B, C. Configuring a conjunction "and" would get you A, B, and C.

ls_ox: bool¶

True

Should fmt_list() use the [Oxford comma][] style?

n_inf: str¶

‘∞’

Rendering for infinite float and decimal.Decimal values, e.g. ∞ and -∞.

If empty ("") falls back to f_fmt, which yields "inf" and "-inf", seemingly independent of the format string.

n_nan: str¶

‘NaN’

Rendering for NaN values of float and decimal.Decimal.

If empty ("") falls back to f_fmt, which yields "nan" (float) and "NaN" (decimal.Decimal), seemingly independent of the format string.

i_fmt: str¶

‘{:,}’

str.format() template for int values.

For i: int, fmt(i, i_fmt=f) → f.format(i). See fmt_number().

Defaults to "{:,}" — thousands-grouped, no decimal point (e.g. 1,000).

f_fmt: str¶

‘{:,g}’

str.format() template for float, and for decimal.Decimal when dec_fmt is empty.

By default uses "{:,g}" — general format (6 significant digits, automatic switch to scientific notation) with comma-separated thousands.

Override for other needs, e.g. f_fmt="${:,.2f}" for currency or f_fmt="{:.1%}" for percent.

dec_fmt: str = <Multiline-String>¶

str.format() template for decimal.Decimal.

When empty (default), Decimal shares f_fmt with float. Set this to target Decimal specifically — handy when it stands in as a “poor-man’s currency” type, e.g. dec_fmt="${:,.2f}".

Q_fmt: str = <Multiline-String>¶

str.format() template for fractions.Fraction.

Named after the common name for the field of rational numbers, \(\mathbb{Q}\).

Empty Fallback

When empty (default), composes formatted attributes as:

fmt(numerator) / fmt(denominator)

As numerator and denominator are int they will be formatted per i_fmt. This allows for additional formatting opportunities without collapsing the fraction to a decimal, but it can also be surprising if unaware.

C_fmt: str = <Multiline-String>¶

str.format() template for complex.

Named after the common name for the field of complex numbers, \(\mathbb{C}\).

Empty Fallback

When empty (default), composes formatted attributes as:

fmt(real) ± fmt(imag)𝒊

complex.real and complex.imag are both float, so f_fmt will come into play in this case. Together with C_i this allows formatting individual components.

C_i: str¶

‘𝒊’

Symbol to use for the Imaginary unit.

Defaults to a mathematics-style \(\mathit{i}\). Python prefers an ASCII j, common in some sciences and engineering, so you may see that when providing C_fmt.

d_fmt: str¶

‘%Y-%m-%d’

Template for formatting datetime.date.

tm_fmt: str¶

‘%H:%M:%S.%3f’

Template for formatting datetime.time.

dt_fmt: str¶

‘%Y-%m-%d %H:%M:%S.%3f %Z’

Template for formatting datetime.datetime.

td_fmt: str¶

‘[%dd] [%H:%M:%S[.%3f]]’

Template for formatting datetime.timedelta, using the timedelta format language (see fmt_timedelta()).

The default "[%dd] [%H:%M:%S[.%3f]]" renders a wall-clock HH:MM:SS with an optional leading Nd days term and an optional trailing .mmm milliseconds term, each included only when the corresponding unit is in-range.

e_trace: bool¶

True

Include tracebacks when formatting exceptions?

pad: Pad = <Multiline-String>¶

Newline padding to add around quoted, multi-line output (see Pad).

A narrow little hack for Markdown correctness: a fenced ```py code block glued directly against preceding text doesn’t render as a code block, so a blank line must separate them. This field lets a caller request that separation on the formatted result.

Only honored by fmt_pretty_repr() when quoting (q=True) a value that pretty-reprs to more than one line — the sole case that emits a fenced block. "s" prepends a blank line, "e" appends one, "se" does both, and "" (the default) leaves it untouched. Single-line quoting uses inline `code` spans and ignores this field.

Currently the only caller that sets it is fmt_type_value(), which uses pad="s" so a <type> value whose value spans multiple lines is preceded by a blank line (and a : separator instead of a space).

splatlog.lib.text.formatter.set_default_fmt_opts(
opts: FmtOpts | None = None,
/,
**kwds: Unpack[FmtKwds],
) → None¶

Set the process-wide default FmtOpts.

@formatter functions (e.g. fmt()) consult this whenever they’re called without explicit options.

Parameters

  • opts: Replace the default with this instance. When None (default), the current default is used as the base.

  • kwds: FmtKwds merged over the base (see FmtOpts.replace()).

Examples

>>> from splatlog.lib.text import fmt

>>> set_default_fmt_opts(i_fmt="{:_}")
>>> fmt(1234567)
'1_234_567'

>>> set_default_fmt_opts(FmtOpts())  # restore the default
>>> fmt(1234567)
'1,234,567'
splatlog.lib.text.formatter.override_fmt_opts(
opts: FmtOpts | None = None,
/,
**kwds: Unpack[FmtKwds],
) → Iterator[FmtOpts]¶

Temporarily override the default FmtOpts within a with block.

The override applies only to the current context (thread/async task) and is restored on exit, leaving the process-wide default (see set_default_fmt_opts()) untouched.

Parameters

  • opts: Base for the override. When None (default), the current effective default (get_default_fmt_opts()) is used.

  • kwds: FmtKwds merged over the base.

Examples

>>> from splatlog.lib.text import fmt

>>> with override_fmt_opts(i_fmt="{:_}"):
...     fmt(1234567)
'1_234_567'

>>> fmt(1234567)
'1,234,567'
class splatlog.lib.text.formatter.Formatter¶

Bases: typing.Protocol

Type of @formatter functions, defining __call__() over a value of parameterized type T and formatting options FmtOpts.

Formatting options can be provided as:

  1. A unified FmtOpts instance in the second position,

  2. attribute-wise as keyword arguments from FmtKwds,

  3. or both, with keyword arguments replacing attributes in the FmtOpts instance.

(1) is handy when passing options between @formatter calls, easing formatter composition. (2) is typically used at the entry-point, and when overriding specific attribute during formatter composition.

Option merging is taken care of in @formatter. Format function implementations always receive a single FmtOpts instance to reference, as visible in the implementation type FmtImpl.

FmtOpts instance are immutable; attribute replacement creates a new instance for the format function implementation to consume.

See Also

  1. FmtOpts

  2. FmtKwds

  3. FmtImpl
