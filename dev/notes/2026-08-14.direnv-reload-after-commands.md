# direnv noise after ordinary commands

## What the dump was

After a command finishes, zsh runs direnv’s precmd hook. If direnv decides the
loaded env is stale, it re-evals `.envrc` **before the next prompt** — so the
messages appear *under* the command output even though the command didn’t cause
them.

With `.envrc` = `use nix` (+ nix-direnv):

1. `direnv: loading …/.envrc` / `using nix` / `Using cached dev shell`
2. ~~`uv sync` stdout~~ — was from `shellHook`; removed
3. `direnv: export +AR +AS …` — impure `use nix` still dumps the whole
   `mkShell` env (noisy but expected)

`git tag` (etc.) was a red herring. Something else invalidated the load; the
next prompt is when you notice.

## Fix applied

- `shell.nix` `shellHook`: only `ZDOTDIR` (no `uv sync` / `activate`)
- `uv sync` + venv activate: explicit (README / local tooling); not on every
  nix/direnv reload
- `.envrc` stays **personal** (gitignored) — direnv is one way to load
  `shell.nix`, not a project requirement. Local example:

  ```bash
  use nix
  export VIRTUAL_ENV="$PWD/.venv"
  PATH_add .venv/bin
  ```

- Do not add `.direnv/` to the repo `.gitignore`; it’s already covered by a
  global excludes file when you use direnv.

## What still invalidates a load

- mtime/content change on `.envrc`, `shell.nix`, or other nix-direnv watches
- nix-direnv cache rebuild under `.direnv/`
- leaving/re-entering the directory
- parent env drift that no longer matches direnv’s recorded diff
