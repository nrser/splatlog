Affinity-Based Object Formatter (Prototype Post-Mortem)
==============================================================================

Notes for prototype work for a writer-based approach to object formatting
intended to use affinity inferred from write patterns to group, breakup, and
breakout output text.

Code was branched-off commit [a8ef157][] in March 2026, which indicates it was a
continuation of work done ~1 month prior. The prototype never reached a working
line-breaking / layout stage — several methods were still `NotImplementedError`
stubs.

[a8ef157]: https://github.com/nrser/splatlog/commit/a8ef1570496cce9c54c241dec64f17af94a58e7b

The codebase has change so significantly that it would be easier to re-write
than rebase onto the current tip. The branch and commits have been removed, but
this note preserves the meaningful code and documents the idea, should we ever
want to reference or reboot.

The Goal
------------------------------------------------------------------------------

Build an object-formatting system that is _smart about layout_:

-   Decide **where to break lines** in long output.
-   Decide **when to render an object inline** (`foo(a, b, c)`) versus as its
    own **block / paragraph** (one item per line, indented).

This is the classic pretty-printer problem (à la Wadler/Leijen "prettier
printer", Python's `black`, `rich.pretty`), but approached from a particular
angle: infer the document's structure implicitly from _how_ formatting code
writes, rather than making authors build an explicit layout tree by hand.


The Core Idea: Affinity From the Writing Pattern
------------------------------------------------------------------------------

The central insight is that the **act of writing carries structural
information**. Instead of asking formatter authors to construct an explicit tree
of "group" / "indent" / "break" nodes, you infer that tree from the shape of the
write calls.

The affinity rules were meant to be:

1.  **Each string written is an atomic chunk.** A single `write("foo")` is
    indivisible — the layout engine will never insert a break inside it.

2.  **Chunks written within the same formatter function have affinity with each
    other.** They form a natural group: a candidate unit that either lays out
    inline together or breaks together.

3.  **Nesting formatters nests groups.** When one formatter calls another
    (`fmt_type.into(f, type(x))` from inside `fmt_type_value`), the callee's
    chunks form a subgroup nested inside the caller's group. Structural depth
    follows call depth.

4.  **Special write ops and context managers annotate the grouping** with intent:
    concatenate tightly, join with a separator, allow/forbid a space, force a
    newline, etc.

The elegant part: an author writes formatting code that reads like straight-line
imperative "print this, then this" code, and the affinity/grouping structure —
the thing a layout engine needs — falls out of that code's structure for free.


The Pieces
------------------------------------------------------------------------------

### `Writer` — the write surface (`writer.py`)

The object every formatter is handed. It wraps a `TextIOBase` and an `Opts`, and
tracks `at_newline` and `indent_level`. Its API is the vocabulary for expressing
affinity (docstrings added here to describe each op's intended role):

```python
type JoinSpace = Literal["never", "opt", "req"]


@dc.dataclass
class Writer:
    io: TextIOBase
    opts: Opts = dc.field(default_factory=Opts)

    at_newline: bool = True
    indent_level: int = 0

    def with_opts(self, **kwds: Unpack[OptsKwds]) -> Self:
        return dc.replace(self, opts=dc.replace(self.opts, **kwds))

    def write(self, text: str) -> None:
        """
        Write one atomic chunk. Empty strings are dropped; strings containing
        `\n` are split into lines. Handles indentation on fresh lines.
        """
        if text == "":
            return

        if "\n" in text:
            return self.write_lines(text.split("\n"))

        # If we're on a new line and have an indent level then write the indent
        # first
        if self.at_newline and self.indent_level:
            self.io.write(" " * self.indent_level)

        self.io.write(text)

        # We handled empty text and text with newlines separately, so we know
        # we're no longer on a new line
        self.at_newline = False

    def write_lines(self, lines: Iterable[str]) -> None:
        for line in lines:
            self.io.write(line)
            self.io.write("\n")

    @contextmanager
    def concat(self):
        """
        Stick chunks written inside together with no break allowed between them
        — the "these belong tightly together" primitive.

        Implemented by swapping `self.io` for a scratch `StringIO`, then writing
        the collected string back as a single chunk.
        """
        chunks = self.io
        self.io = StringIO()
        yield
        s = self.io.getvalue()
        self.io = chunks
        self.write(s)

    def join(
        self,
        sep: str,
        *,
        space: JoinSpace | tuple[JoinSpace, JoinSpace] = "never",
    ) -> ContextManager:
        """
        Interleave `sep` between the chunks written inside, adding `space`
        around it — both sides or different before and after.

        The key layout hook, and NEVER IMPLEMENTED: a join is exactly the place
        where the engine would choose inline (`a, b, c`) vs. block (one per
        line).
        """
        raise NotImplementedError("TODO")

    def space(self) -> None:
        """Insert a single space between the neighbors written before and after."""
        self.io.write(" ")
        self.at_newline = False

    def write_obj(self, obj: object) -> None:
        """Write `repr(obj)` — the trivial fallback."""
        self.write(repr(obj))

    def write_fmt(self, obj: object) -> None:
        """Write a nested formatted object. NEVER IMPLEMENTED."""
        raise NotImplementedError("TODO")

    def newline(self) -> None:
        """Hard line break; marks `at_newline`."""
        self.io.write("\n")
        self.at_newline = True

    def p(self, *items):
        """Write a paragraph of mixed strings and formattable objects."""
        for item in items:
            if isinstance(item, str):
                self.write(item)
            else:
                self.write_fmt(item)
```

The `JoinSpace` vocabulary (`"never" | "opt" | "req"`) is worth keeping: it
distinguishes "no space", "space only if laid out inline", and "always a space" —
which is precisely the nuance a separator needs across inline vs. block layout.

### `Formatter` — typed, composable formatter wrapper (`formatter.py`)

A frozen, generic dataclass `Formatter[**P]` wrapping a
`Callable[Concatenate[Writer, P], None]`. Created via the `@formatter`
decorator, which supports both bare use and use with option kwargs:

```python
@formatter
def fmt_type(f: Writer, x: type) -> None: ...

@formatter(fqn=False)
def fmt_something(f: Writer, x) -> None: ...
```

The source, with the mechanics called out inline:

```python
# `ParamSpec` (`P`) preserves each formatter's real argument signature through
# the wrapper — callers keep full type-checking on the formatting args, with the
# leading `Writer` spliced in via `Concatenate`. The two overloads let `@formatter`
# be used both bare and with option kwargs.
@overload
def formatter[**P](
    **kwds: Unpack[OptsKwds],
) -> Callable[[Callable[Concatenate[Writer, P], None]], Formatter[P]]: ...


@overload
def formatter[**P](
    fn: Callable[Concatenate[Writer, P], None],
    /,
) -> Formatter[P]: ...


def formatter[**P](
    fn: Callable[Concatenate[Writer, P], None] | None = None,
    /,
    **kwds: Unpack[OptsKwds],
):
    def wrap(
        fn: Callable[Concatenate[Writer, P], None],
        /,
    ) -> Formatter[P]:
        return Formatter(fn=fn, opts=Opts(**kwds))

    if fn is None:
        return wrap

    return wrap(fn)


@dc.dataclass(frozen=True)
class Formatter[**P]:
    fn: Callable[Concatenate[Writer, P], None]
    opts: Opts = dc.field(default_factory=Opts)

    def __post_init__(self):
        # Carry `fn.__doc__` onto the (frozen) instance via `object.__setattr__`
        # so the wrapped formatter still carries a docstring and can be doctested.
        # Formatters like `fmt_routine` keep runnable `>>>` examples this way.
        if self.fn.__doc__:
            object.__setattr__(self, "__doc__", self.fn.__doc__)

    def with_opts(self, **kwds: Unpack[OptsKwds]) -> Self:
        """Return a copy with tweaked `Opts`, e.g. `fmt_routine.with_opts(fqn=False)`."""
        return dc.replace(self, opts=dc.replace(self.opts, **kwds))

    def into(self, f: Writer, *args: P.args, **kwds: P.kwargs) -> None:
        """
        Run the formatter's function against an EXISTING writer — the composition
        primitive. This is how one formatter nests inside another and inherits the
        shared write stream (and thus contributes chunks to the caller's group).
        """
        # TODO  This would need handling before and after to group the output
        #       from the call together
        self.fn(f, *args, **kwds)

    def __call__(self, *args: P.args, **kwds: P.kwargs) -> FmtOut:
        """Top-level entry: build a fresh `ChunkIO` + `Writer`, run `into`, return the string."""
        io = ChunkIO()
        f = Writer(io=io, opts=self.opts)
        self.into(f, *args, **kwds)
        return io.getvalue()
```

The critical unfinished hook is that `TODO` on `into`: the "before and after" is
exactly where each formatter call would open/close its affinity group. Without
it, the write stream is flat — the structure the whole design depends on was
never actually recorded.

### The `@formatter` functions (`__init__.py`)

The actual formatters — the most illustrative part, since they show how the
writer vocabulary was meant to be used. Note the composition via `.into(f, ...)`
(nesting a formatter onto the shared writer), the `with f.concat():` / `f.space()`
pairs for tight-then-spaced layout, and the `with f.join(...)` calls that were
supposed to drive inline-vs-block for unions, tuples, sets, and callables.

````python
@formatter
def fmt(f: Writer, x: object) -> None:
    if is_typing(x):
        return fmt_type_hint.into(f, x)

    if isinstance(x, type):
        return fmt_type.into(f, x)

    if isroutine(x):
        return fmt_routine.into(f, x)

    f.write_obj(x)


@formatter
def fmt_name(f: Writer, named: object):
    name = (
        getattr(named, "__qualname__", None)
        or getattr(named, "__name__", None)
        or str(named)
    )

    if (
        f.opts.fqn
        and (mod_name := get_module_name(named))
        and (mod_name != BUILTINS_MODULE or f.opts.fq_builtins)
    ):
        f.write(mod_name)
        f.write(FQN_SEP)
    f.write(name)


@formatter
def fmt_routine(f: Writer, x: Routine) -> None:
    """
    Format a function or method for display.

    Lambdas are shown as `λ()`. Named functions include their qualified name
    followed by `()`.

    ## Examples

    ```python
    >>> import datetime

    >>> fmt_routine(datetime.date.today)
    'datetime.date.today()'

    >>> fmt_routine.with_opts(fqn=False)(datetime.date.today)
    'date.today()'

    >>> fmt_routine(lambda x, y: x + y)
    'λ()'
    ```
    """
    if x.__name__ == LAMBDA_NAME:
        f.write("λ()")
        return

    fmt_name.into(f, x)
    f.write("()")


@formatter
def fmt_type(f: Writer, x: type) -> None:
    if f.opts.fqn and (x.__module__ != BUILTINS_MODULE or f.opts.fq_builtins):
        f.write(x.__module__)
        f.write(FQN_SEP)
    f.write(x.__qualname__)


@formatter
def fmt_type_value(f: Writer, x: object) -> None:
    with f.concat():
        fmt_type.into(f, type(x))
        f.write(":")
    f.space()
    fmt.into(f, x)


@formatter
def fmt_type_hint(f: Writer, x: Any) -> None:
    if x is Ellipsis:
        f.write("...")
        return

    if x is types.NoneType:
        f.write("None")
        return

    if isinstance(x, ForwardRef):
        f.write(x.__forward_arg__)
        return

    if isinstance(x, TypeVar):
        f.write_obj(x)
        return

    origin = get_origin(x)
    args = get_args(x)

    if args == ():
        if isclass(origin):
            return fmt_type.into(f, origin)
        elif isclass(x):
            return fmt_type.into(f, x)
        else:
            warn("expected typing|origin with no args to be type")
            return f.write_obj(origin or x)

    if origin is Union or origin is Literal:
        with f.join("|", space="opt"):
            for arg in args:
                fmt_type_hint.into(f, arg)
        return

    if origin is dict:
        f.write("{")
        with f.concat():
            fmt_type_hint.into(f, args[0])
            f.write(":")
        f.space()
        fmt_type_hint.into(f, args[1])
        f.write("}")
        return

    if origin is list:
        with f.concat():
            fmt_type_hint.into(f, args[0])
            f.write("[]")
        return

    if origin is tuple:
        f.write("(")
        with f.join(",", space=("never", "req")):
            for arg in args:
                fmt_type_hint.into(f, arg)
        f.write(")")
        return

    if origin is set:
        f.write("{")
        with f.join(",", space=("never", "req")):
            for arg in args:
                fmt_type_hint.into(f, arg)
        f.write("}")
        return

    if origin is Callable:
        f.write("(")
        with f.join(",", space=("never", "req")):
            for arg in args[0]:
                fmt_type_hint.into(f, arg)
        f.write(")")
        f.space()
        f.write("->")
        f.space()
        fmt_type_hint.into(f, args[1])
        return

    f.write_obj(x)
````


What Worked
------------------------------------------------------------------------------

-   The `@formatter` decorator ergonomics: bare vs. parameterized, `ParamSpec`
    signature preservation, `with_opts`, docstring/doctest carry-over.
-   `into` as the nesting/composition primitive shared across formatters.
-   `concat()` via `StringIO` swap — a clean, working "keep tight" primitive.
-   The dispatch in `fmt()` (typing construct → type → routine → fallback) and
    the readable type-hint rendering in `fmt_type_hint` (`X | Y`, `T[]`,
    `{K: V}`, `(A, B)`, `(A) -> B`), which reads much nicer than stdlib `repr`.


What Was Never Built (the hard part)
------------------------------------------------------------------------------

-   `Writer.join(...)` — the separator/space logic; the primary inline-vs-block
    decision point.
-   `Writer.write_fmt(...)` — nested-object formatting.
-   `Formatter.into` group-open/close — the "before and after" that would have
    actually recorded affinity into the chunk tree.
-   Any **layout / line-breaking pass**. `ChunkIO` keeps a `list[str | Chunks]`
    ready for a tree, but nothing writes nesting into it and nothing consumes it
    for layout. The entire "smart about where to break" payoff was never reached.

In short: the _authoring model_ (how you write formatters) was largely worked
out and pleasant; the _layout engine_ (what turns affinity into wrapped,
indented output) was never started.


Ideas Worth Keeping
------------------------------------------------------------------------------

1.  **Infer layout structure from write-call structure.** Affinity from "same
    function = same group, nested call = nested group" is a genuinely nice way to
    avoid hand-building layout trees. The trick is that `into` must bracket each
    call with group open/close so the structure is actually captured.

2.  **`JoinSpace` = `never | opt | req`.** A small but expressive vocabulary for
    separators that behave differently inline vs. broken.

3.  **Chunks as a nested list, flattened lazily.** `ChunkIO` is the right shape
    for the tree; it just needs the writer to push/pop levels.

4.  **Compare against a real pretty-printer algorithm** before any revival —
    Wadler/Leijen `Doc` combinators (`group`, `nest`, `line`, `<>`), `rich`'s
    measurement/console-width model, or `prettier`'s doc IR. The affinity idea is
    essentially a way to _generate_ such a `Doc` from imperative code; pairing it
    with a proven layout algorithm is likely the shortest path to something that
    works.
